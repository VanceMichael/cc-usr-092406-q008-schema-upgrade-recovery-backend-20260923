# q008 水产养殖服务

本项目是水产养殖管理后端，维护塘口、养殖批次、投苗、投喂、水质、用药、成本、销售与周期分析数据。业务数据保存在 SQLite 文件中，HTTP 接口由 FastAPI 提供。

## 结构版本与可恢复迁移

旧版本只有建表（`create_all`）逻辑：空数据库正常，但沿用旧 SQLite 文件的实例仍停留在旧表结构，请求会报缺列；多进程同时启动还会各自初始化。现在结构由 `backend/app/migrations/` 按版本管理，每一版都明确登记**前置版本、校验摘要与升级后不变量**。

| 版本 | 前置版本 | 内容 | 变更方式 |
| --- | --- | --- | --- |
| v1 | — | 历史基线（9 张业务表，无版本记录） | — |
| v2 | v1 | `ponds.location_code`、`batches.notes` | 事务内 `ALTER TABLE ADD COLUMN`，升级前后比对结构摘要 |
| v3 | v2 | `ponds.pond_code` 必填唯一、`ponds.species` 必填 | SQLite 不支持该类表变更，采用**可回滚的复制**：建新表 → 分批复制（断点续传）→ 行数与逐行哈希校验 → 单事务内换名并重建索引/外键校验 |

每个版本在内存库中按权威 DDL 计算 sha256 **结构摘要**（表、列、外键、索引），启动时重算比对；摘要不符即拒绝猜测式推进。

### 单一迁移者与其他进程的行为

- 迁移锁为库内单行表 `schema_migration_lock`，带所有者与心跳。同一数据库**只有一个迁移者**；其他进程轮询等待。
- 迁移者心跳超时（默认 30s，视为进程死亡）后，等待者**接管锁**，依据断点继续——已提交的批次不会重复搬运。
- 等待期间或结构未就绪时，进程 `/health/live` 可探活，但业务接口 `/api/*` 一律返回 `503`（带 `code` 与 `Retry-After`），不以旧结构接流量。

### 中断后的决策：继续 / 回退 / 人工介入

- **继续**：影子表与断点（`last_copied_id`/`rows_copied`）一致 → 只复制断点之后的行，绝不重复搬运。
- **回退本次尝试**：影子表损坏但源表结构摘要仍匹配源版本 → 删除影子表与断点、从头重新复制；线上表从未被触碰。每版升级前还会用 SQLite Online Backup 生成 `数据库文件.v<N>.bak`。
- **人工介入（blocked）**：换名已提交后不变量失败、源/目标摘要均不匹配等。已提交的高版本**绝不自动降级**，健康接口持续报 `blocked`，需用备份恢复或修正数据后重启。
- **未来版本禁止启动**：库内版本高于本程序支持的最高版本时，拒绝启动并报 `future_version`，不会降级打开。

### 健康接口（三态分离）

- `GET /health/live`：进程存活，事件循环在响应即 200，不依赖数据库。
- `GET /health/ready`（`GET /health` 同义）：同时校验**进程存活、数据库可用、结构就绪（版本=当前且摘要匹配）**；任一不满足返回 503，body 的 `checks` 分别给出 `process` / `database` / `schema`（`ready`、`migrating`、`blocked`、`future_version`、`uninitialized` 等）。

### 可调参数（环境变量）

`MIGRATION_LOCK_STALE_SECONDS`（心跳过期秒数，默认 30）、`MIGRATION_WAIT_TIMEOUT_SECONDS`（等待者单轮等待，默认 60）、`MIGRATION_COPY_BATCH_SIZE`（复制批大小，默认 500）、`DATABASE_URL`（SQLite 文件路径）。

## 测试命令

```bash
# 全部自动化测试（含真实多进程互斥、硬崩溃接管、故障注入恢复）
python3 -m unittest discover -s tests -v
```

测试覆盖场景：

- **全新库**：空文件直接初始化为当前版本并可读写；
- **跨至少两个旧版本升级**：无版本记录的 v1 库 → v2 → v3，校验补码/补值/外键/摘要；
- **故障注入**：复制中途崩溃后断点继续且不重复搬运、影子表损坏自动回退重试、换名后崩溃重启完成；
- **保留数据库后的重启**：同一文件第二次部署为无操作，旧数据可被 ORM 读出；
- **并发**：4 个进程同时启动恰好一个迁移者；迁移者被硬杀（`os._exit`，不释放锁）后等待者心跳接管；
- **拒绝态**：未来版本禁止降级；不变量违反转人工且不回退；健康三态与 503 门控。

## 编译与构建命令

```bash
python3 -m compileall -q backend/app
```

## 启动命令

```bash
cd backend
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

启动后访问 `/health/live` 探活、`/health/ready`（或 `/health`）确认数据库可用与结构就绪；就绪前 `/api/*` 返回 503。开发环境不得提交真实账号、连接凭据或生产数据。
